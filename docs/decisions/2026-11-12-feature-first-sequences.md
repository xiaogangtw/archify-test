# 決策：序列圖由功能來源分析先提供

日期：2026-11-12
狀態：已接受

## 背景
使用者需要先從前端理解功能互動，再規劃測試。僅將序列圖放於案例會使零案例功能無法閱讀，顛倒操作順序。靜態 import 可達 API 不能證明實際先後；功能結構、測試意圖及執行結果仍須分開，延續 [測試關聯決策](2026-11-08-test-traceability.md)。

## 決策
使用者後續確認主要目的為「讓 API 測試與前端操作順序一致」，初版序列圖不利閱讀，因此功能詳情的主要呈現改為預設可見的操作／API／資料傳遞／等待條件表，來源收合。此補充調整下述序列資料的呈現方式，資料歸屬仍在功能；案例結果保持獨立。sequence 增加選填 api／transfer，未知不由參與者名稱推測；舊 baseline 下次分析以 sequenceVersion=2 補齊一次。
前端功能 AI 分析輸出有來源及條件的 sequence，保存於 feature.frontend.sequence；功能詳情先呈現序列圖，無案例亦可閱讀。網站不另開圖庫，不以案例結果著色功能互動。案例保留 steps.interaction 與保守的逐步報告配對，不自動猜測兩者對應。

既有 schemaVersion 1 以選填欄位相容；舊分析下次由使用者發起分析時完整升級一次，之後恢復增量。來源 hash 不符時保留舊圖並明示過期，不補造互動。

## 影響
先理解再規劃，沿用既有頁面、來源預覽與受控 AI 契約。模型判讀仍需來源核對，片段不足顯示缺口，不推測後端內部流程；不代表已執行或已查明根因。此補充不改產品 API、路由、權限或 DB。
