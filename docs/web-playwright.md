## 入口與版面

沿用 E2E 自動化測試側欄的 Web Playwright（web-e2e，路由描述 /e2e/web；實際沿用既有 App 導覽）。入口參照 Android Appium：頂部連線狀態與預設收起的環境資訊，中央為畫面工作區。沒有批次／撰寫模式分頁、常駐案例列表或舊草稿區。

畫面上方「選擇案例」開啟浮動選單，提供緊湊案例勾選列、各列編輯與新增案例；不推擠畫面。情境估算放在選單底部，順序明細再收起。選單支援 Tab 操作原生按鈕與核取方塊、Escape 關閉並返回觸發鈕、點外側關閉；與 Appium 相同，不因焦點移動而關閉選單。進入編輯時自動收起選單與環境資訊。

點案例列「編輯」或「新增案例」後進入撰寫。頂部有返回畫面、可編輯名稱與唯一儲存案例按鈕，其下為測試網址與預設收起的測試設定；每次進入編輯都重設為收起。桌面左側 AI 對話、右側網頁／流程預覽，下方完整展開 TypeScript；窄螢幕依序垂直排列。返回畫面保留已儲存案例，未儲存時先確認；放棄後清除該次編輯並回到收起選單的畫面。所有版面 token 由 apps/web/tailwind.config.ts 管理，沿用固定淺色與共用控制項。

編輯頁沿用 Appium 的 compact 共用控制項密度與 text-menu／text-body 層級，桌面對話與預覽採等寬雙欄。聊天使用 canvas 標頭與輸入區、surface 訊息區、brand-soft 使用者訊息；輸入區提供圖示傳送／停止，Enter 傳送、Shift+Enter 換行並尊重中文組字狀態。TypeScript 使用相同等寬字級與展開編輯高度。未增加 Appium 的實際操作能力或聊天紀錄工具。

## 案例與保存

編輯頂部名稱列使用與既有案例撰寫相同的左向 chevron 返回圖示，提供「返回畫面」可存取名稱與 tooltip。案例名稱以 aria-label 標記，不另外占用一行可見標籤；桌面返回、名稱與操作垂直置中，窄螢幕返回與名稱同列，操作可換至下一列。

每個案例保存名稱、網址、環境名稱、登入方式意圖、瀏覽器、手機尺寸、輸入組、檢查規則、範圍／預期、腳本及對話。網址僅接受不含帳密的 HTTP／HTTPS；必填名稱、環境、腳本，每組選項至少一項。這是保存檢查，不是 TypeScript 格式檢查或可執行性證明。

使用 archify.web-playwright.v1.<projectId> 的 localStorage，只在目前瀏覽器保存，不同步伺服器、不產生正式案例版本或執行紀錄。儲存失敗保留編輯內容；讀取資料結構或 JSON 失敗時禁止覆寫。新案例使用空對話，重新編輯保存案例會恢復其對話。離開頁面、切換專案或開啟另一案例時，未保存內容及 AI 建議會觸發既有離頁保護；重新整理使用瀏覽器離頁提示。

依使用者要求移除舊版 Web 草稿：開啟工作台時讀取目前專案的 archify.e2e-plans.v1.<projectId>，僅移除 platform:web 項目；若剩餘 Android／其他項目則寫回保留，沒有剩餘項目時刪除該鍵。未開啟專案不清理，新版 archify.web-playwright.v1.<projectId> 不刪除。資料毀損或寫入失敗時顯示清理錯誤，不猜測刪除其他內容。舊草稿沒有匯入或唯讀入口。

## AI 資料流

沿用 POST /api/llm，purpose:author、agentId:code 與 projectId，使用既有模型連線，不增加協定欄位。傳入設定、目前腳本、最近 12 則有界對話及本次需求。AI 僅提供文字回覆與 source 建議；沒有 DOM、截圖、瀏覽器操作或登入工具，不因使用者輸入網址而取得網頁證據。未知定位器及業務預期應詢問，不能推測成已驗證資料。

source 在建議區預覽，套用前與請求起點的原稿比較；原稿已變更則停用套用，保留人工內容。建議未處理時不能保存或再送新請求；套用後仍須儲存案例。停止或離頁會中止等待，忽略後續回覆，不宣稱能撤回模型端已開始的工作。API 或模型失敗顯示錯誤，不生成假回覆。

## 批次與預覽

案例按勾選順序列入批次，情境數為各案例的瀏覽器數 × 尺寸數 × 輸入組數之和；檢查規則不增加情境數。選項是意圖，尚未生成測試資料、注入 LIFF 狀態或轉成 Worker 參數。

流程預覽沿用 previewSteps，只辨識具名 await test.step 字串，不解析任意 TypeScript，所有步驟標為未執行。腳本可匯出 web-case.spec.ts。尚無格式檢查、截圖基準、差異圖或真實結果。

## 執行邊界與驗證

現有 Runner 固定內建 Smoke 網址，launcher 網路隔離不變。此工作台尚未接入外部 Playwright Worker、串流或 LIFF 工作階段；開啟網頁與開始批次執行明示停用。主畫面與編輯預覽沿用 Appium 手機外框的視覺，顯示未連接狀態；外框不是實際視窗尺寸或截圖，不提供假操作、iframe 或示範通過。

後續若接入真實瀏覽器，需另行實作目標存取限制、工作階段隔離、登入／秘密參照、案例快照與結果證據。Chromium／WebKit 手機尺寸驗證仍不等同 LINE 真機 WebView 與鍵盤驗收。

本機回歸：先 npm run build --prefix apps/web，再 node scripts/verify-web-playwright-ui.mjs。腳本使用可解析的 Playwright 套件（可透過 NODE_PATH）與 CHROME_PATH，預設使用 Windows Chrome。測試中的模型回覆為替身，不代表實際模型連線、LIFF 或部署驗收；不保存截圖。
