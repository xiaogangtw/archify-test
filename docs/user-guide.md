## 五步核心操作與功能益處

1. **準備與分析（工作區與知識）**
   - **功能益處**：本機隔離保護 Git/Key；規格語意去重防幻覺；自動掃描全站路由免翻代碼。
   - **操作步驟**：❶ 設定路徑 ➔ ❷ 匯入規格 ➔ ❸ 分析功能。

2. **AI 規劃案例（計畫先行）**
   - **功能益處**：計畫先行可審核；寫入 `catalog.json` 資產重用；依功能邊界約束防幻覺。
   - **操作步驟**：❶ 複製任務 ➔ ❷ 貼給 AI 規劃 ➔ ❸ 網站核對步驟。

3. **AI 實作腳本（1:1 對齊）**
   - **功能益處**：1:1 步驟對齊定位精確；標準 fixture 自動攔截截圖；TypeScript 型別防退化。
   - **操作步驟**：❶ 複製指令 ➔ ❷ AI 產出腳本 ➔ ❸ 核對步驟對齊。

4. **門檻與執行（防假綠燈）**
   - **功能益處**：雙門檻攔截語法錯與假 skip；本機終端安全受控執行；產出單檔零依賴報告。
   - **操作步驟**：❶ 型別門檻 ➔ ❷ 截圖門檻 ➔ ❸ 指定執行。

5. **查收圖文結果（現場證據）**
   - **功能益處**：圖文報告保存截圖與網絡診斷，0 秒重現；清單追蹤版本相符度；流程核對原始規格。
   - **操作步驟**：❶ 重新讀取 ➔ ❷ 清單核對 ➔ ❸ 審查報告截圖。

## 實戰教學提示

- 測試專案必須獨立在平台與原始碼外（例如 `aiwow_test`）自行 Git 版控；前端有更動先按「重新掃描前端」。
- 腳本必須從 `support/web-test.js` 引用 `test` 與 `expect`；善用 `toBeVisible()` 避免寫死固定等待。
- 失敗時嚴禁私自放寬斷言；直接查驗單檔 HTML 報告中失敗當步的截圖與請求診斷。
- 單檔 HTML 報告零依賴，可直接郵寄或傳給團隊查閱。

案例先區分 target: web（畫面操作）與 target: api（請求回應）。第三步分為畫面與 API 兩個任務區塊，各自提供對應 skill、腳本位置與檢查方式。

準備與分析提供四個內嵌 mock 畫面，可切換查看工作區設定、知識匯入、前端分析與 AI 功能分析；示意控制項不會修改產品設定。
