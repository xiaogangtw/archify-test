# 決策：前端 API 消失後確認封存腳本

日期：2026-11-07
狀態：已接受

## 背景
使用者希望前端移除 API 時一起移除測試，既有測試可能已補資料與斷言。靜態分析缺少呼叫證據也可能來自解析限制、範圍或來源專案改變，不能直接等同產品 API 被刪除。

## 決策
先追蹤有單一 archify-id 標記、與分析記錄及預期路徑對應的 .spec.ts，索引保存在獨立專案 analysis 目錄。首次只建立基準，不猜測舊檔。來源絕對位置、來源子範圍與輸出位置形成 scope；換電腦或路徑改變時重新建立基準，不跨來源推論移除。

只有來源根目錄完整掃描、至少一個來源檔且無解析警告時才提供移除候選。同 ID 仍存在、同名 GraphQL 內容變更或相同來源檔可能是修改的操作，都保留；同 ID 多腳本及標記不符的腳本不清理。這是保守的候選清單，不證明後端停用。

使用者選取並確認後，再次掃描來源、核對快照及腳本 hash，將原文複製到 legacy/removed-api/台北日期時間/files 並保存 manifest，再移出 tests。不刪除共用設定、fixtures、skills、知識與歷史報告。不透過 Git 推論或執行產品測試。還原使用 exclusive copy，任何目標已存在則整批預檢拒絕覆寫；封存保留。

## 影響
保留人工測試內容、可還原並可一起版控。代價是有解析警告、子目錄掃描或疑似修改時不提供移除建議；需要人工釐清。跨多檔不是 DB 交易，異常會嘗試從封存回復已移出的原檔並回報封存位置，還原失敗的部分仍可人工處理。路徑檢查與 hash 不是抵抗同帳號惡意競態的 OS 沙箱。網頁提供本次操作的還原按鈕，重新整理後可依 manifest 手動還原或以本機契約指定封存識別。
